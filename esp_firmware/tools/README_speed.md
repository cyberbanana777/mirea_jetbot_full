# Быстрый контур скорости (M/T + feedforward + ПИ / LADRC)

## Что изменилось
- **Оценка скорости**: `speed_estimator.h`. Прерывание энкодера запоминает счётчик фронтов и время последнего фронта; скорость = фронты / интервал между фронтами (метод M/T). Скользящее среднее на 5 значений убрано.
- **Контур**: 100 Гц (было 10 Гц), `CONTROL_PERIOD_US` в `config.h`.
- **Регулятор**: u = sign(v)·(FF_DEADZONE + FF_GAIN·|v|) + ПИ. Жёсткая «мёртвая линия» 0.35 заменена feedforward-ом; интеграл сбрасывается при остановке и смене знака и не копится, пока колесо разгоняется к уставке не дольше 300 мс после ступеньки уставки (`INT_FREEZE_*` в `motor_controller.cpp`): без этого интеграл, набранный за разгон, давал перерегулирование 20-30%.
- **Одометрия** (`getXAndReset`) не тронута, идёт на 50 Гц.
- **I2C** 400 кГц; дисплей отправляется кусками только в свободном окне перед следующим тактом.
- **NVS-пространство** сменено на `"Memory2"`: старые Kp/Ki из флэша не подхватятся (они подобраны под 10 Гц). Калибровка и ПИД сохранятся заново.

## Протокол
| Направление | Команда | Формат | Смысл |
|---|---|---|---|
| ПК → ESP | 10 | `$10;dL;dR;#` | открытый контур, скважность −1…1 |
| ПК → ESP | 11 | `$11;gainL;dzL;gainR;dzR;save#` | параметры feedforward, save=1 пишет во флэш |
| ПК → ESP | 12 | `$12;on;#` | телеметрия 100 Гц |
| ПК → ESP | 13 | `$13;#` | запрос feedforward ($4), фильтра уставки ($6) и регулятора ($7) |
| ПК → ESP | 14 | `$14;tau;save#` | фильтр уставки, с |
| ПК → ESP | 15 | `$15;mode;save#` | регулятор: 0 - ПИ, 1 - LADRC (безударно, можно на ходу) |
| ПК → ESP | 16 | `$16;wc;wo;b0L;b0R;ff;save#` | параметры LADRC (ff: 0 нет прямой подачи, 1 мёртвая зона, 2 полный FF) |
| ПК → ESP | 17 | `$17;#` | запрос регулятора и LADRC ($7) |
| ESP → ПК | 3 | `$3;t_us;refL;vL;uL;refR;vR;uR;#` | телеметрия |
| ESP → ПК | 4 | `$4;gainL;dzL;gainR;dzR;#` | текущий feedforward |
| ESP → ПК | 6 | `$6;tau;#` | фильтр уставки |
| ESP → ПК | 7 | `$7;mode;wc;wo;b0L;b0R;ff;#` | регулятор и параметры LADRC |

Без команд дольше 1 с: аварийная остановка, телеметрия выключается.

## Калибровка (колёса в воздухе!)
```
pip install pyserial numpy
python3 tools/mtcal.py run --port /dev/ttyUSB0          # посмотреть результат
```

Фазы: разгон (страгивание), статическая характеристика (dz, Kv), ступенька (Tm, L). ПИ по IMC: Kp = Tm/(K(λ+L)), Ki = Kp/Tm, λ = max(0.5·Tm, 2L).

## Ограничения и допущения
- На реальном ESP32 **не собиралось** (не было тулчейна): проверено на заглушках Arduino и модели двигателя. Цифры симуляции (Tm 80 мс, мёртвая зона 0.33 и т. п.) мои допущения, реальные даст лог с железа.
- `MAX_CONSTRUCTIVE_VELOCITY = 0.5` м/с ограничивает уставку ≈1.96 об/с. Для 3.5 об/с нужно ≥ 0.894 м/с.
- 0.05 об/с: при трогании возможен заброс из-за трения покоя.
- Если шумит скорость на малых оборотах, смотрите `SPEED_MIN_EDGES` (1 быстрее, 2 по умолчанию, 4 гладко, но задержка).
- 400 кГц на шине I2C предполагает нормальную разводку и подтяжки.

## Трогание и нагрузка
- Пока колесо стоит при ненулевой уставке, скважность растёт со скоростью `STUCK_RAMP_RATE` (0.3/с), чтобы преодолеть трение покоя. На полу страгивание заметно выше, чем в воздухе.
- Калибровка `mtcal.py` делается с поднятыми колёсами; на полу feedforward занижен, и недостающее добирает интеграл ПИ.

## Результаты на роботе (пол, steptest.py, ступенька с места)
| Уставка, об/с | t90, мс | Перерегулирование, % |
|---|---|---|
| 1.0 | 230-390 | 14-22 |
| 0.5 | 270-300 | 35 |
| 0.2 | 310-430 | 91-97, устанавливается за ~2 с |
| 0.1 | - | 240-340, колесо дёргается (stick-slip) |

Старая схема (10 Гц, скользящее среднее по 5) выходила на скорость за 1.5 с и дольше.
- Низкие скорости *из состояния покоя* на полу ограничены трением покоя (страгивание около 0.4 ШИМ при трении движения около 0.3). Практический минимум на полу около 0.2-0.3 об/с.
- Попытка сбрасывать интеграл после страгивания дала пилу (колесо останавливается снова): люфт редуктора даёт короткие микродвижения, которые принимаются за страгивание. Откачено.
- Ступенька с места даёт перерегулирование; при плавных уставках (cmd_vel с ускорением) его не будет. Ограничитель ускорения уставки - возможное улучшение.

## Синхронность колёс: общая λ и фильтр уставки

* `python3 mtcal.py fit cal_log.csv --lambda-s 0.2` - ПИ обоих колёс считается под одну и ту же желаемую постоянную замкнутого контура λ = 0.2 с (вместо λ = lam·Tm у каждого колеса своя).
* `$14;tau_s;save#` - постоянная фильтра уставки (первого порядка, одинаковая для обоих колёс), save=1 - во flash. `$14;0;0#` отключает фильтр. Ответ на `$13;#` дополнен `$6;tau;#`. Значение по умолчанию - `REF_TAU_S` в `config.h`.
* Нулевая уставка и аварийная остановка обходят фильтр: остановка мгновенная.
* В телеметрии `$3` столбцы ref - это уже отфильтрованное задание.

## LADRC (прошивка 2.4.0)

Второй регулятор скорости, выбирается командой `$15` (по умолчанию ПИ, поведение прошлой версии не изменилось).
Модель колеса: $\dot v = b_0 u + f$, где $f$ - всё неизвестное (инерция, трение, нагрузка, ошибка калибровки).
Наблюдатель расширенного состояния (ESO, Эйлер, шаг 10 мс) оценивает $z_1 \approx v$, $z_2 \approx f$:

$$e = v - z_1,\quad z_1 \mathrel{+}= h\,(z_2 + b_0 u_{eso} + 2\omega_o e),\quad z_2 \mathrel{+}= h\,\omega_o^2 e,$$
$$u = u_{ff} + \frac{\omega_c (r - z_1) - z_2}{b_0},\qquad u_{eso} = \operatorname{sat}(u) - u_{ff}.$$

* `wc`, `wo` общие для обоих колёс (одинаковая желаемая динамика $1/(s/\omega_c+1)$), `b0` у каждого колеса свой.
* `ff` - прямая подача по калибровке `$11`: 0 - чистый LADRC, 1 - мёртвая зона, 2 - полный статический FF.
  Без неё на полу старт с места медленный: наблюдатель после каждого старта заново «ищет» ~0.3 скважности.
* В наблюдатель идёт реально поданная (ограниченная) скважность - заброса при насыщении нет.
* Старт, реверс, остановка: оценки сбрасываются (как интеграл ПИ). Фильтр уставки `$14` работает и для LADRC.
* Переключение ПИ ↔ LADRC и смена параметров на ходу безударные: состояние нового регулятора подбирается так,
  чтобы скважность на следующем такте совпала с последней.
* Заводские значения (`config.h`, настроено на полу 29.10.2026): регулятор LADRC (`CTRL_MODE = 1`), wc 9, wo 40, b0 9.82 / 7.65, ff 2; FF по полу 0.5151 / 0.2992 / 0.8424 / 0.3101; фильтр уставки 0. Во flash - ключи `CtrlMode`, `AdrcWc`, `AdrcWo`, `AdrcB0L`, `AdrcB0R`, `AdrcFf`: сохранённые значения главнее заводских.

Ограничения настройки: $\omega_o \Delta t \le 0.5$ ($\omega_o \le 50$ при 100 Гц), $\omega_o L \lesssim 1.5$,
$\omega_o \approx 3\text{-}5\,\omega_c$, $1/\omega_c \ge 2L$. $b_0$ лучше завысить, чем занизить.

### Скрипты
```
python3 tools/adrc.py fit cal_log.csv --lambda-s 0.2      # b0 = K/Tm по калибровке, wc = 1/lambda, wo = 5 wc, команда $16
python3 tools/adrc.py show --port /dev/ttyUSB0            # что в плате
python3 tools/adrc.py mode ladrc --port /dev/ttyUSB0       # выбрать LADRC (с сохранением; --no-save - до перезагрузки)
python3 tools/adrc.py set --port /dev/ttyUSB0 --wc 9 --wo 40   # поменять часть параметров (с сохранением)

# сравнение на одинаковых ступеньках, настройки только на время опыта:
python3 tools/steptest.py run --port /dev/ttyUSB0 --levels 0.2,0.5,1.2 --mode pi
python3 tools/steptest.py run --port /dev/ttyUSB0 --levels 0.2,0.5,1.2 --mode ladrc --adrc 5,25,9.82,7.65,2
python3 tools/steptest.py compare step_log_pi.csv step_log_ladrc.csv --names ПИ,LADRC
```
Открытие порта перезагружает плату, поэтому несохранённые настройки живут только внутри одного запуска скрипта.
`steptest` теперь печатает и синхронность колёс: max|wL − wR| и набег курса (`--base`, по умолчанию 0.1775 м).

## Шум скорости: неравномерная квадратура и окно из целых меток
Опыт на роботе (`noisetest.py`, колёса в воздухе) показал иглы скорости 1,5-7 %, которые в фронтах энкодера
постоянны (0,4-0,55 фронта на такт на скоростях 0,7-2,6 об/с), а в микросекундах нет. Значит, это не дрожание
меток времени, а ошибка положения фронтов: один из 4 фронтов метки сдвинут примерно на полинтервала.

Исправление (`SPEED_ALIGN_QUAD = true` в `config.h`): прерывание энкодера хранит время последнего фронта
каждого из 4 типов (`snapshot*Phases`), а оценка скорости (`MTSpeedEstimator::updateAligned`) берёт окно из
целого числа меток - от фронта одного типа до последнего фронта того же типа. Ограничение «скорость не выше,
чем один фронт за прошедшее время» тоже считается по целой метке. Цена: окно кончается до 3 фронтов раньше,
на разгоне 4 об/с² отставание оценки 6,7 мс вместо 5,3 мс. Одометрия не менялась.

Тест `host_test/test_estimator_aligned` (квадратура с перекосом 0,5 интервала): прежняя оценка 0,5-12,7 % СКО,
с целыми метками меньше 0,01 %.

Проверка на роботе:
```
python3 tools/noisetest.py run --port /dev/ttyUSB0          # колёса в воздухе, режимы 2:0 (прежняя) и 2:1 (целые метки)
python3 tools/noisetest.py fit noise_log.csv
```
Команда `$18;n;align#` (до перезагрузки, ответ `$8;n;align;#`): n - минимум фронтов в окне, align 1 - целые метки.
Главная метрика - «иглы»: 95-й процентиль отклонения от скользящей медианы, в %, фронтах и мкс.
