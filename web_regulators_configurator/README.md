# web_regulators_configurator

Веб-настройщик ПИД-регуляторов колёс jetbot_mirea. Узел работает **на роботе**
и сам раздаёт страницу: открываете `http://<IP робота>:8080` с ноутбука или
телефона в той же сети — и настраиваете регуляторы. На ноутбуке не нужны ни ROS,
ни провод к ESP32.

Умеет то же, что `simple_regulators_configurator_pkg` и `simple_PID_configurator`,
плюс уставка на графиках, ступенчатый тест с расчётом показателей и защита
«мёртвая рука».

## Запуск

```bash
# вместе с остальными драйверами робота
ros2 launch completed_scripts_jetbot jetbot_sensors_and_motors.launch.py enable_web_configurator:=True

# отдельно (нужен запущенный serial_bridge_cpp)
ros2 launch web_regulators_configurator web_configurator.launch.py
```

В логе узла появится `Веб-настройщик ПИД: http://0.0.0.0:8080`. Откройте в
браузере `http://<IP робота>:8080` (IP показывает OLED-дисплей робота).

**Docker.** Страница доступна снаружи контейнера, только если контейнер запущен с
`--network host` (так обычно и делают для ROS 2) или с пробросом порта `-p 8080:8080`.

## Что на странице

- **Движение.** Скорость базы (v, ω) или скорости колёс. «Ехать» включает команду,
  «Остановить» выключает.
- **ПИД.** Шесть коэффициентов (под полями — текущие значения в ESP32):
  «Получить текущие» (`$5`), «Текущие → в поля», «Установить» (`$3`, до
  перезагрузки ESP32), «Записать во flash» (`$4`, с подтверждением). После
  установки узел сам запрашивает коэффициенты, чтобы показать, что ESP32 их принял.
  Галочка «Одинаковые для обоих колёс» копирует левые значения в правые.
- **Ступенчатый тест.** Уставка (колёса или база) и **длительность**; робот
  отрабатывает ступеньку, останавливается, и страница показывает показатели
  для каждого сигнала с ненулевой уставкой, график отклика и даёт скачать CSV.
- **Графики** v, ω, левого и правого колеса: сплошная линия — измерено, пунктир —
  уставка. Окно 5–30 с, пауза.
- **Лог** отправленных (→) и принятых (←) кадров и событий (•).
- **СТОП** — кнопка в шапке, пробел или Esc.

## Безопасность

Прошивка ESP32 (≥ 2.1.0) останавливает робота, если команд нет дольше 1 с.
Поэтому:

- пока команда движения активна, узел **повторяет её 5 раз в секунду**;
- страница каждые 250 мс шлёт heartbeat; если его нет дольше `heartbeat_timeout`
  (1 с), узел снимает команду и отправляет `$1;0;0;#`;
- при закрытии или сворачивании вкладки страница сразу отправляет СТОП —
  **держите вкладку активной**, пока робот едет;
- при остановке узла (Ctrl+C, SIGTERM) он отправляет `$1;0;0;#`;
- скорости ограничиваются `max_linear`, `max_angular`, `max_wheel_speed`;
- если у `/cmd_vel` есть другие издатели (Nav2, teleop), в шапке появится
  предупреждение: их команды и команды настройщика будут перебивать друг друга.

Пароля нет: сервер рассчитан на локальную сеть робота. Чтобы закрыть доступ из
других сетей, задайте `host` конкретным адресом интерфейса.

## Ступенчатый тест: показатели

Считаются по отрезку ступеньки `[0, длительность]`:

| Показатель | Определение |
|---|---|
| Нарастание | время от 10 % до 90 % уставки, с |
| Перерегулирование | $\frac{\max y - r}{r} \cdot 100\,\%$ (0, если не было) |
| Установление | время, после которого отклик до конца ступеньки остаётся в полосе ±5 % уставки, с |
| Ошибка | $r - \bar y$, где $\bar y$ — среднее за последние 25 % ступеньки (в единицах сигнала и в %) |

Скорости приходят из прошивки уже сглаженными (скользящее среднее по 5 периодам
ПИД, 0.5 с) — это те же значения, по которым работает ПИД. Поэтому время
нарастания включает задержку этого фильтра.

CSV (`step_test.csv`): `time_s, signal, value, setpoint`, время от начала
ступеньки, сигналы `v`, `w`, `vl`, `vr`; после ступеньки ещё 1 с записи торможения.

## Параметры узла

| Параметр | По умолчанию | Описание |
|---|---|---|
| `host` | `0.0.0.0` | адрес HTTP-сервера |
| `port` | `8080` | порт |
| `telemetry_rate` | `10.0` | частота отправки телеметрии на страницу, Гц (точки на графиках приходят все, пачками) |
| `command_repeat_rate` | `5.0` | частота повтора активной команды, Гц |
| `heartbeat_timeout` | `1.0` | через сколько секунд без heartbeat от страницы робот останавливается |
| `max_linear` | `0.4` | ограничение линейной скорости, м/с |
| `max_angular` | `4.0` | ограничение угловой скорости, рад/с |
| `max_wheel_speed` | `0.4` | ограничение скорости колеса, м/с (как в прошивке) |
| `wheel_base` | `0.1775` | колея, м (для пересчёта уставок база ↔ колёса) |
| `step_test_max_duration` | `10.0` | максимальная длительность ступенчатого теста, с |
| `step_test_default_duration` | `3.0` | длительность по умолчанию на странице, с |
| `step_test_tail` | `1.0` | сколько секунд записывать после ступеньки |
| `history_seconds` | `30.0` | глубина истории для новых вкладок, с |
| `cmd_topic` | `/low_level/serial/cmd` | куда отправлять команды |
| `feedback_topic` | `/low_level/serial/feedback` | откуда брать кадры ESP32 |
| `log_odometry_frames` | `false` | показывать кадры одометрии в логе (50 в секунду) |
| `static_dir` | `""` | каталог страницы (пусто — из пакета) |

## Как устроено

```
браузер ──GET /, /static/*────────────►┐
        ◄─GET /events (SSE, 10 Гц)──────┤  узел web_regulators_configurator
        ──POST /api/*──────────────────►┘  (rclpy + http.server, без pip-зависимостей)
                                             │ публикует /low_level/serial/cmd
                                             │ подписан на /low_level/serial/feedback
                                             ▼
                                      serial_bridge_cpp ──► ESP32
```

- Данные берутся из сырых кадров ESP32 (`$1;x;y;θ;v;ω;v_l;v_r;#`, `$2;ПИД;#`),
  которые публикует `serial_bridge_cpp` (параметр `publish_raw_feedback`, по
  умолчанию `true`). Одна подписка на лёгкий `String` вместо `/odom`, скоростей
  колёс и `/PIDcoeffs`: в rclpy каждый колбэк и разбор `Odometry` заметно стоят CPU.
- Подписка **ленивая**: она существует, только пока открыта страница или робот
  выполняет команду. Без клиентов узел почти не тратит процессор.
- Страница — один HTML, CSS и JS без внешних библиотек и CDN (у робота может не
  быть интернета); графики нарисованы на canvas.
- Логика без ROS (протокол, хранилище телеметрии, «мёртвая рука», ступенчатый
  тест) — в отдельных модулях с тестами (`test/`).

API (JSON): `POST /api/heartbeat`, `/api/stop`, `/api/command {mode: base|wheels, a, b}`,
`/api/pid/set {pid}`, `/api/pid/flash {pid}`, `/api/pid/request`,
`/api/step_test/start {mode, a, b, duration}`, `/api/step_test/abort`;
`GET /api/step_test/recording`, `/api/step_test/result.csv`.

## Если что-то не работает

- **«ESP32: нет данных».** Запущен ли `serial_bridge_cpp` и включён ли у него
  `publish_raw_feedback` (по умолчанию да)? Проверка: `ros2 topic hz /low_level/serial/feedback`.
- **Страница не открывается с ноутбука.** Робот и ноутбук в одной сети? Docker
  запущен с `--network host` или `-p 8080:8080`? Не занят ли порт (`port:=8081`)?
- **Робот останавливается сам через секунду.** Вкладка свернута или неактивна, либо
  связь с роботом рвётся (heartbeat не доходит).
- **Робот дёргается, команды «перебивают».** Одновременно работает Nav2 или teleop
  (см. предупреждение в шапке).
